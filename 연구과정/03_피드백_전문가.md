## 1. 서사(Narrative) 구조 보완

### 현재 서사의 문제점

내러티브 4단계가 인과 체인처럼 연결되어 있으나, 두 고리가 실제로 끊겨 있음.

```
P1 ──→ P2 : 연결 없음
  MERT 최악 클래스 (sul_p / col_l)
  ≠ ALM 최악 클래스 (ordinario / tremolo)
  → "라벨 부족 → ALM 한계"의 인과가 아닌 단순 병렬 발견

P3 ──→ P4 : 상관관계만 있음 (개입 실험 미수행)
  "Flux 경계가 도메인 이동에 유지 안 된다"는 추론이지
  실험으로 검증된 인과 아님
```

### 수정 제안: 더 정직하고 강한 주장으로 재프레이밍

> "수동 특징 공학(Spectral Flux)이 제한 라벨 환경에서 SSL 대형 모델(MERT)과
> ALM(Qwen2-Audio) 양쪽을 동시에 능가하며, 그 이유를 SHAP으로 설명하고
> 교차 도메인에서도 부분적으로 재현된다."

이 주장이 지금 데이터로 실제로 방어 가능한 가장 강한 버전임.

## 3. Phase별 구체 보완 사항

### Phase 1 — Self-Training

**핵심 누락: SVM의 seed별 성능 비교 테이블**

현재 테이블에는 SVM의 50% seed 성능(0.916)만 있고, 5%/10%/20% 성능이 없음.
Foundation model + self-training이 "언제 SVM보다 유리한가"라는 교차점을 보여주지 못함.

```
추가해야 할 테이블:

| seed | CLAP 기준선 | SVM   | MERT baseline | MERT + ST (τ=0.7) |
|------|------------|-------|---------------|-------------------|
| 5%   | 0.363      | ???   | 0.671         | 0.745             |
| 10%  | 0.363      | ???   | 0.711         | 0.817             |
| 20%  | 0.363      | ???   | 0.777         | 0.837             |
| 50%  | 0.363      | 0.916 | 0.834         | 0.857             |
```

**기대 결과**: 5%/10% 구간에서 MERT+ST > SVM 교차점 존재 가능
→ "Foundation model은 라벨이 부족할 때 유리하다"는 실용적 결론 완성
→ 작업: SVM을 seed별 데이터 비율로 제한 학습 + 동일 LOSO 평가 (2~3시간)

### Phase 4 — 교차 도메인 일반화

**재프레이밍 필요**

0.423 → 0.461(+3.8%p)의 절대값이 낮음.
"실패"가 아니라 **"어떤 클래스가 왜 도메인 이동에 취약한지를 설명하는 것"** 자체가 기여.

```
강조할 발견:
col_legno_battuto / sul_ponticello
→ self-training 후에도 F1 = 0.000
→ pseudo-label 채택률 0%
→ Phase 3의 Flux 경계가 도메인 간 유지 안 됨 (가설)
→ "취약 클래스의 구조적 특성 규명"이 기여
```

**개입 실험 추가 (인과관계 확보)**

```

1. ordinario 클립 10~20개 선택

결과 해석:
- 이동 있음 → P2-P3 인과관계 직접 증거
- 이동 없음 → "flux 때문"이라는 해석 재검토 필요 (더 복잡한 발견)
```

#### 🥇 1순위 — Onset-Region 분리 특징 추출

**임팩트**: 높음 / **작업량**: 반나절 / **novelty**: 있음

현재 방식: 클립 전체의 통계량(mean/std/q75) 추출
문제: col_legno(타격 어택), sul_ponticello(지속 고조파)의 핵심 정보가
      서로 다른 시간 구간에 있으나 구분 없이 평균화됨

```python
# 구현 방향
import librosa

def extract_region_features(y, sr):
    # 1. onset 위치 감지
    onsets = librosa.onset.onset_detect(y=y, sr=sr, units='samples')
    onset_idx = onsets[0] if len(onsets) > 0 else 0

    # 2. 어택 구간 (onset 전후 50ms)
    attack_window = int(0.05 * sr)
    y_attack = y[max(0, onset_idx - attack_window):onset_idx + attack_window]

    # 3. 지속 구간 (onset 이후 전체)
    y_sustain = y[onset_idx + attack_window:]

    # 4. 각 구간별 독립 특징 추출
    flux_attack = compute_flux(y_attack, sr)
    flux_sustain = compute_flux(y_sustain, sr)
    mfcc_attack = extract_mfcc_stats(y_attack, sr)
    mfcc_sustain = extract_mfcc_stats(y_sustain, sr)

    return np.concatenate([flux_attack, flux_sustain, mfcc_attack, mfcc_sustain])
```

**서사 연결**: Phase 3에서 Flux가 1위로 나온 이유를
"어떤 구간의 Flux인지"로 한 단계 더 분해하는 논리적 확장

**주의사항**:
- OrchideaSOL 단음 클립에서 어택 구간이 클립 길이 대비 매우 짧을 수 있음
- onset_detect 신뢰도를 클래스별로 먼저 확인 필요
- 어택 너무 짧으면 window를 30ms/70ms/100ms로 sensitivity 실험

#### 🥈 2순위 — PSO 기반 특징 선택

**임팩트**: 중간~높음 / **작업량**: 하루 / **novelty**: 높음 (IE 배경 차별화)

```
현재 feature 수: ~245차원
- MFCC+Δ+ΔΔ: 156차원 (SHAP per-feature 0.023)
- Chroma:      48차원 (SHAP per-feature 0.004 → 거의 무효)
- Spectral:    28차원
- RMS:          4차원
- ZCR:          4차원
- Flux:         4차원 (SHAP per-feature 0.481 → 1위)
- Log Attack:   1차원
```

**PSO 설계**:
```python
# pyswarms 기반
import pyswarms as ps

def objective_function(position_matrix, X, y, groups):
    """position: 각 차원을 포함할지(1) 말지(0)의 이진 벡터"""
    macro_f1_list = []
    for position in position_matrix:
        selected_features = np.where(position > 0.5)[0]
        if len(selected_features) == 0:
            macro_f1_list.append(0.0)
            continue
        X_sub = X[:, selected_features]
        # LOSO GroupKFold F1 계산
        f1 = loso_macro_f1(X_sub, y, groups)
        macro_f1_list.append(f1)
    return [1 - f1 for f1 in macro_f1_list]  # PSO는 최소화하므로 1-F1

# 설정
options = {'c1': 0.5, 'c2': 0.3, 'w': 0.9, 'k': 30, 'p': 2}
optimizer = ps.discrete.BinaryPSO(
    n_particles=30, dimensions=245, options=options
)
```

**GA 비교 실험 추가**: `deap` 라이브러리로 GA도 같이 돌려서
수렴 속도/최종 선택 feature 수/F1 차이를 비교 → 방법론 섹션 풍부해짐

**M5 계산량 주의사항**:
- 입자 30개 × 세대 50회 × LOSO(4-fold) = 6,000번 SVM 학습
- 사전 테스트: n_particles=5, iterations=5로 예상 1회 소요 시간 측정
- 예상 총 시간: SVM 1회 0.1초 가정 시 → 약 10분 (현실적)

#### 4순위 — 스태킹 앙상블

**임팩트**: 즉각적 F1 향상 / **작업량**: 반나절 / **novelty**: 낮음

```python
from sklearn.ensemble import StackingClassifier
from sklearn.linear_model import LogisticRegression

base_models = [
    ('svm', SVC(probability=True, ...)),
    ('xgb', XGBClassifier(...)),
    ('cnn_proba', CNNWrapper())  # softmax 출력
]

meta_learner = LogisticRegression(max_iter=1000)

stacking = StackingClassifier(
    estimators=base_models,
    final_estimator=meta_learner,
    cv=GroupKFold(n_splits=4),  # LOSO와 동일한 그룹 분할 필수
    passthrough=False
)
```

**Leakage 방지 필수 구조**:
```
LOSO Fold i (test: 악기 i):
  ├── train fold (악기 i 제외)
  │     ├── base model 학습 (inner LOSO)
  │     └── out-of-fold 예측 → meta-learner 학습
  └── test fold (악기 i)
        └── 최종 예측
```

**예상 성능**: 0.92~0.94 (현재 SVM 0.916 대비 소폭 향상)
