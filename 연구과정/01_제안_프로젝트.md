# 현악기 연주기법 분류 모델 — 프로젝트 제안서

> **목표 한 줄 요약**
> 음악 전공 배경을 차별점으로 활용해, "강건하고 범용적인 분류 모델 경험"과 "MIR 도메인 전문성"을 동시에 쌓는 포트폴리오 프로젝트.
> **핵심 조합:** 현악기 연주기법 분류기 → 특징 엔지니어링 → XGBoost/SVM 비교 → Feature Importance 분석 → (확장) CNN 비교

---

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| **과제** | 현악기 연주기법(Arco / Pizzicato / Tremolo / Spiccato 등) 자동 분류 |
| **1차 접근** | 오디오 특징 추출 → 통계 집계 → XGBoost / SVM 분류 (해석 중심) |
| **2차 확장** | mel-spectrogram → CNN 분류 (현장 표준 접근과 비교) |
| **산출물** | Jupyter Notebook (재현 가능), Feature Importance 분석, 두 접근의 트레이드오프 비교 |
| **연결 가치** | 향후 "Lesson Assist" 연습 피드백 기능의 기반 모듈 |

### 왜 "악기 분류"가 아니라 "연주기법 분류"인가
1. **음악 전공 지식 활용** — 도메인 해석이 차별점이 됨
2. **MIR스러움** — 단순 분류를 넘어 음향학적 추론이 들어감
3. **범용 ML 기술 습득** — 특징 엔지니어링·모델 비교·평가 설계 경험
4. **Feature Engineering 경험** — 프로젝트의 진짜 알맹이
5. **확장성** — 연습 피드백·기법 교정으로 자연스럽게 연결

> **면접 프레이밍**
> "악기 분류 해봤습니다" → 흔함
> "현악기 연주기법 분류 모델을 만들었고, 어떤 특징이 어떤 기법에 결정적이었는지 음향학적으로 설명할 수 있습니다" → 드묾

## 2. 모델 선택 근거

학습 효과 순서로 본 모델 비교:

| 모델 | 장점 | 단점 | 이 프로젝트에서의 역할 |
|---|---|---|---|
| **Random Forest** | 매우 강건, 적은 데이터 OK, Feature Importance 제공, 과적합 적음 | 복잡한 패턴 한계 | **베이스라인** |
| **XGBoost** | 표 데이터 최강급, 캐글 검증됨 | 튜닝 필요 | **주력 모델** |
| **SVM** | 데이터 적을 때 강함, MIR 전통 강자 | 데이터 커지면 느림 | **비교 모델** |
| **CNN** | 스펙트로그램 이미지 분류 가능 | 데이터 많이 필요 | **2차 확장(v2)** |
| **Transformer** | 최신 | 현재 단계에서는 과함 | 보류 |

**결론:** "강건·범용 분류 경험"이 목표라면 표 데이터 + XGBoost + Feature Importance 루트가 정확히 맞다(해석 가능 + 전이성 높음). 단, MIR 연구실 현장은 spectrogram + CNN으로 가 있으므로 **v2로 CNN을 붙여 두 접근을 비교**하는 것이 최종 목표.

## 3. 검토 및 보완 사항 (Review & Refinement)

> 위 방향은 유지하되, 실제로 굴려보면 무너지는 가정들을 우선순위 순으로 보완한다.

### 3.1 [최우선] 데이터가 가장 큰 리스크다
연주기법 분류의 성패는 모델이 아니라 **"기법별 라벨링된 오디오를 어디서 구하냐"**에 달려 있다. 악기 분류는 데이터셋이 넘치지만(NSynth, IRMAS 등) 기법 라벨은 희소하다.

- ✅ **OrchideaSOL (권장)** — Ircam SOL 데이터셋의 축소판으로 **52종의 연주기법 라벨**과 기법별 분포를 제공. 무료지만 Ircam Forum 가입 필요.
- ⚠️ **TinySOL은 사용 불가** — 이름이 비슷해 헷갈리지만, TinySOL은 **전부 "ordinario(평주법)"만 담고 확장 기법은 일부러 제외**했다. 기법 분류엔 무용지물. (다수가 여기서 첫 삽을 잘못 뜸)
- ⚠️ **클래스 불균형** — OrchideaSOL은 **200개 이상 샘플을 가진 기법이 52종 중 12종뿐**. Spiccato 등은 샘플이 적을 수 있으니, 클래스 설계 전에 샘플 수부터 카운트할 것.

### 3.2 Chroma는 기법 분류에서 "최약체" 특징이다
원안은 MFCC / Spectral Contrast / Chroma를 동급으로 비교하라고 했으나, **Chroma는 음높이(pitch class) 정보**라 음색·주법 차이엔 일부러 둔감하게 설계됐다. Pizzicato와 Arco는 같은 음높이로도 연주 가능하므로 Chroma로는 구분이 안 된다.

진짜 변별력은 **시간축/과도부(transient) 특징**에 있다 — Pizz는 날카로운 어택 후 빠른 감쇠, Arco는 지속음이라 어택·엔벨로프가 결정적.

| 특징 | 기법 변별력 | 이유 |
|---|---|---|
| Log-Attack-Time, Temporal Centroid | ★★★ | Pizz/Spiccato 짧은 어택 vs Arco 지속음 |
| Spectral Flux / ZCR | ★★★ | 과도부·잡음성 (활 소음, 트레몰로 진동) 포착 |
| MFCC (+Δ, ΔΔ) | ★★ | 전반적 음색 + 시간 변화 |
| Spectral Contrast | ★★ | 배음 구조 차이 |
| Chroma | ☆ | 음높이 정보 — **음성 대조군(negative control)으로만 의미** |

> Chroma를 빼는 게 아니라 "왜 안 되는지 증명하는 대조군"으로 재배치 → 면접에서 오히려 깊이가 드러남.

### 3.3 [핵심 누락 단계] 프레임 → 고정벡터 집계
오디오는 길이가 제각각이고 XGBoost는 고정 길이 표 데이터를 입력으로 받는다. 프레임 단위 특징을 **통계량으로 집계**하는 단계가 이 프로젝트의 진짜 엔지니어링 알맹이다.

```python
import librosa, numpy as np

def extract_features(y, sr):
    mfcc = librosa.feature.mfcc(y=y, sr=sr, n_mfcc=13)
    flux = librosa.onset.onset_strength(y=y, sr=sr)
    zcr  = librosa.feature.zero_crossing_rate(y)
    feats = []
    for f in [mfcc, np.atleast_2d(flux), zcr]:
        feats += [f.mean(1), f.std(1),
                  np.percentile(f, 25, axis=1),
                  np.percentile(f, 75, axis=1)]
    return np.concatenate(feats)   # 길이 고정 벡터
```

> 평균만 쓰지 말 것. std·분위수·델타까지 넣어야 "시간적 변화"가 살아남는다.

### 3.4 데이터 누수(leakage)를 막아라 — 오디오 ML 자기기만 1순위
같은 녹음/같은 악기의 다른 음이 train과 test에 동시에 들어가면 정확도가 뻥튀기된다.
- OrchideaSOL은 **악기·기법·음역·강약 분포를 맞춘 공식 5-fold 분할**을 메타데이터로 제공 → 그대로 사용.
- 직접 분할 시 `GroupKFold` (group = 악기/녹음 단위).

### 3.5 클래스 셋을 "쉬운 것 + 어려운 것"으로 섞어라
Pizz vs Arco는 너무 쉬워 99%가 나오고 끝 → 배우는 게 없다.
- **쉬운 축:** Arco vs Pizzicato (어택 엔벨로프만으로 분리)
- **어려운 축:** Spiccato / Détaché / Martelé / Staccato 등 보잉 아티큘레이션, Tremolo vs 지속 Arco

> 어려운 클래스에서 어떤 특징이 결정적이었는지를 Feature Importance로 풀어내는 것이 진짜 스토리.

### 3.6 v1 → v2 비교가 최종 한 방
| 단계 | 접근 | 학습 포인트 |
|---|---|---|
| **v1** | 특징 엔지니어링 + XGBoost / SVM | 해석성, 특징 설계, 모델 비교 |
| **v2** | mel-spectrogram + 작은 CNN | 딥러닝 접근, 현장 표준 |
| **비교** | 정확도 / 해석성 / 데이터 요구량 트레이드오프 | **희소한 차별점** |

> 단일 모델 자랑보다, 트레이드오프를 직접 측정해본 경험이 훨씬 드물다.

## 4. 실행 로드맵

1. **데이터 확보** — Ircam Forum 가입 → OrchideaSOL 다운로드 → 현악 기법별 샘플 수 카운트
2. **클래스 확정** — 쉬운/어려운 기법을 섞어 4~5개 선정 (샘플 수 균형 고려)
3. **특징 추출 파이프라인** — 시간축 특징 중심 + MFCC/Spectral Contrast, Chroma는 대조군
4. **집계 & 분할** — 통계 집계 벡터화 + 공식 5-fold(또는 GroupKFold)
5. **v1 모델링** — RF 베이스라인 → XGBoost(튜닝) → SVM 비교
6. **해석** — Feature Importance / SHAP으로 "기법별 결정적 특징" 도출
7. **v2 확장** — mel-spectrogram + CNN, 동일 평가 프로토콜로 비교
8. **문서화** — 노트북 + 비교 표 + 음향학적 해석 서술
