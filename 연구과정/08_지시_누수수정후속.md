# 누수 수정 후속 지시서 — 세 가지 결함 수정 시 주의사항 (Claude Code 작업용)

> 배경: STEP 1 감사에서 결함 A(Phase 1 iteration을 test F1로 선택),
> 결함 B(Phase 4 τ를 Pool B로 선택), 결함 C(단일 fold cherry-picking)가 확인됨.
> 사용자 결정: A=검증셋 기반 선택 / B=검증셋 기반 선택 / 범위=누수 수정 + 유의성 검정 한 번에.
>
> 이 문서는 그 수정을 실행할 때 **"누수를 고쳤다면서 다른 형태의 누수를 남기는" 실수를 막기 위한
> 구체 주의사항**이다. 각 결함마다 반드시 지킬 것.

## 결함 A — Phase 1 self-training iteration 선택 누수 수정

### 지켜야 할 데이터 분리 구조

```
labeled seed   → head 학습 (early-stop용 val 이미 cell 9에서 사용 중)
unlabeled pool → pseudo-labeling 대상
                 ⚠ 이 pool에서 절대 iteration-선택용 val을 떼지 말 것
held-out val   → iteration 선택 전용 (pseudo-labeling에 사용되지 않는 데이터)
test           → 최종 1회만 평가
```

### 핵심 주의점: 두 종류의 val을 혼동하지 말 것
- **early-stop용 val** (cell 9, 정상): "한 iteration 내부에서 head 학습을 언제 멈출지" 결정.
- **iteration-선택용 val** (신규 필요): "몇 번째 iteration을 최종 채택할지" 결정.
- 이 둘은 층위가 다르다. 같은 val로 둘 다 하면 그 val에 이중 최적화되어 또 다른 누수가 된다.
- **원칙**: 가능하면 분리한다. 데이터가 부족하면 최소한
  **"iteration-선택용 val은 test와 완전히 분리"**만은 절대적으로 지킨다.

### 수정 대상
- `notebooks/04_phase1.ipynb` cell 15: `'best_st_f1': max(result['iter_f1'])` 제거.
- `iter_f1`를 test가 아닌 held-out val에서 계산하도록 self_training 함수 수정.
- best iteration은 **val F1로 선택**, 그 iteration의 **test F1을 보고**.

## 결함 B — Phase 4 τ 선택 누수 수정 (권장: OrchideaSOL val에서 τ 고정)

### 두 가지 대안 중 2번을 권장

**1번 (Nested)**: Pool A+V를 합쳐 내부 교차검증으로 τ 선택, Pool B는 최종 평가만.

**2번 (권장) — 소스 도메인에서 τ 고정**:
```
OrchideaSOL 내부 val에서 τ를 미리 결정
        ↓ (타깃 도메인 정보 전혀 사용 안 함)
그 τ를 Philharmonia에 그대로 적용
        ↓
Pool B는 최종 평가 1회만
```

### 2번을 권장하는 이유
- col_legno_battuto가 원래 소수라, Pool을 3분할하면 τ 선택셋·평가셋이 클래스당 한 자릿수가 되어
  τ 선택 자체가 노이즈에 휘둘린다.
- 2번은 **"타깃 도메인 라벨을 전혀 보지 않고 정한 τ가 새 도메인에서 작동하는가"**를 측정 →
  이것이 진짜 cross-domain 질문이며, 방법론적 강점이 된다.
- 논문에 "타깃 도메인 정보 없이 τ를 고정했다"고 명시 가능.

### 수정 대상
- `src/phase4_crossdomain.py:481`: `best_tau = df_summary.groupby('tau')['pool_b_f1'].max().idxmax()` 제거.
- τ를 OrchideaSOL val 기반으로 결정하는 로직으로 교체.
- Pool B F1은 선택이 아닌 **최종 보고 목적으로만** 1회 계산.

### 사전 확인 요청
- 이 방식으로 바꿀 때 기존 Pool A/B 분할 코드를 얼마나 수정해야 하는지 먼저 파악해서 보고할 것.
- Pool A/B 분할을 만드는 함수/셀 위치를 찾아, 갈아엎는 범위를 추정 후 알려줄 것.

## 유의성 검정 — 규모 현실을 반영할 것

### 검정 방식
- **paired 검정 사용**: LOSO fold별로 baseline↔self-training이 짝지어지므로 paired 구조.
- fold가 4개뿐 → 정규성 가정 불가 → **Wilcoxon signed-rank test** (paired t-test보다 적절).

### 반드시 각오할 것: 검정력 부족
- **fold 4개로는 p<0.05가 수학적으로 거의 나오지 않는다.**
- 억지로 "유의하다"고 쓰지 말 것. 그게 더 위험하다.
- **정직한 보고 문구**: "향상은 관찰되나 fold 수가 적어 통계적 유의성은 확정할 수 없다."
- 리뷰어는 LOSO n=4 규모를 알면 이 한계를 납득한다.

### 다중비교 처리
- seed별·모델별을 전부 검정하면 다중비교 보정(Holm-Bonferroni)이 필요하나,
  이미 검정력이 낮은 상황에서 보정까지 하면 아무것도 안 나온다.
- **현실적 방침**: 사전에 정한 **주 실험(primary) 하나만 검정**, 나머지는 기술통계로만 보고.

## 작업 순서

```
1. 결함 B 수정 범위 사전 파악 (Pool A/B 분할 코드 위치·범위 보고)
2. 결함 A 수정 (iteration 선택을 val 기반으로) + 재실행
3. 결함 B 수정 (τ를 OrchideaSOL val에서 고정) + 재실행
4. 결함 C 수정 (전 결과를 4-fold 평균±표준편차로 통일)
5. 유의성 검정 (주 실험 1개, Wilcoxon, 정직한 한계 보고)
6. ★ 누수 제거 전후 비교표 생성 → 보고 (여기서 멈추고 방향 논의)
```

**6번에서 일단 멈출 것.** 비교표를 보고 연구 질문 방향을 확정한 뒤 다음 단계(ALM 확장 등)로 간다.
